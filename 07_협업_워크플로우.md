# 7. 협업 워크플로우

> 팀에서 Git을 효과적으로 사용하는 방법을 학습합니다.

---

## 주요 워크플로우 종류

| 워크플로우 | 적합한 팀 | 복잡도 |
|-----------|-----------|--------|
| GitHub Flow | 소규모, CD | 낮음 |
| Git Flow | 대규모, 배포 스케줄 | 중간 |
| Trunk-Based | DevOps, CI/CD | 높음 |

---

## GitHub Flow

소규모 팀에 적합한 간소화된 워크플로우입니다.

```
┌─────────────────────────────────────────────────────────────┐
│                      GitHub Flow                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   1. main에서 시작                                           │
│   main ───●────●────●                                       │
│                                                             │
│   2. 새 브랜치 생성                                          │
│   main ───●────●────●                                       │
│                └── feature/login ───●──●                   │
│                                                             │
│   3. 작업 후 Push                                           │
│                                                             │
│   4. Pull Request 생성 ──▶ 리뷰 ──▶ 병합                     │
│                                                             │
│   5. 즉시 배포                                               │
│   main ───●────●────●─────────────────●                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 단계별 가이드

```bash
# 1. main에서 시작
git checkout main
git pull origin main

# 2. 새 브랜치 생성
git checkout -b feature/amazing-feature

# 3. 작업 후 커밋
git add .
git commit -m "feat: add amazing feature"

# 4. 정기적으로 Push
git push -u origin feature/amazing-feature

# 5. GitHub에서 Pull Request 생성
#    - 제목, 설명 작성
#    - 리뷰어 지정
#    - 코드 리뷰

# 6. 병합 후 브랜치 정리
git checkout main
git pull origin main
git branch -d feature/amazing-feature
```

## Git Flow

대규모 팀, 정기적 배포에 적합합니다.

```
main (production) ───────────────────────────▶
    │                                         
    │◀── hotfix ────▶│                        
    │                │                        
develop ◀── release ─┘                        
    │                                       
    └── feature ──▶                          
```

| 브랜치 | 용도 | 예시 |
|--------|------|------|
| `main` | 배포 코드 | v1.0.0 |
| `develop` | 다음 출시 통합 | |
| `feature/*` | 새 기능 | feature/user-auth |
| `release/*` | 출시 준비 | release/v1.1.0 |
| `hotfix/*` | 급한 수정 | hotfix/security |

### 설치

```bash
# macOS
brew install git-flow

# Linux
apt-get install git-flow

# 초기화
git flow init
# 기본값: main, develop, feature/, release/, hotfix/, support/
# version prefix []: (빈값)
```

### 주요 명령어

```bash
# Feature 시작
git flow feature start login

# Feature 완료 (develop에 병합)
git flow feature finish login

# Feature Publish (원격에推送)
git flow feature publish login

# Release 시작
git flow release start v1.0.0

# Release 완료 (main + develop에 병합)
git flow release finish v1.0.0

# Hotfix 시작
git flow hotfix start security-bug

# Hotfix 완료
git flow hotfix finish security-bug
```

## Fork & Pull Request

오픈소스 프로젝트에 기여할 때 사용합니다.

```
원본 저장소: facebook/react
    │
    └── Fork ──▶ 내 저장소: username/react
                        │
                        ├── Clone ──▶ 내 컴퓨터
                        │
                        └── Pull Request ──▶ 원본에 병합 요청
```

### 단계별 가이드

```bash
# 1. GitHub에서 Fork 클릭

# 2. 내 계정의 저장소 복제
git clone https://github.com/my-username/react.git
cd react

# 3. 원본을 upstream으로 추가
git remote add upstream https://github.com/facebook/react.git

# 4. 새 브랜치에서 작업
git checkout -b fix-bug
# 작업...
git add .
git commit -m "fix: resolve bug"

# 5. 내 저장소에 Push
git push origin fix-bug

# 6. GitHub에서 Pull Request 생성

# 7. 원본 저장소 동기화 유지
git fetch upstream
git checkout main
git merge upstream/main
git push origin main
```

## Pull Request 관리

### PR 생성

```bash
# GitHub CLI 사용
gh pr create --title "Add feature" --body "Description"

# 브랜치에서 바로
gh pr create --fill
```

### PR 리뷰

```bash
# PR 목록
gh pr list

# PR 상세
gh pr view 123

# 코드 리뷰
gh pr review 123 --approve
# 또는
gh pr review 123 --request-changes -b "의견"

# 병합
gh pr merge 123 --squash

# 병합 방식:
# --squash   : 스쿼시 병합
# --merge     : 일반 병합
# --rebase    : 리베이스 병합
```

## 코드 리뷰 포인트

PR을 리뷰할 때 확인할 사항:

- ✅ **기능**: 요구사항을 만족하는가?
- ✅ **코드 품질**: 가독성, 일관성
- ✅ **테스트**: 적절한 테스트가 있는가?
- ✅ **성능**: 병목이 없는가?
- ✅ **보안**: 취약점이 없는가?
- ✅ **문서**: 필요한 문서가 있는가?

## 충돌 해결

PR 생성 시 충돌이 있으면 해결해야 합니다.

```bash
# 1. main으로 이동
git checkout main
git pull origin main

# 2. 내 브랜치로 이동
git checkout feature/my-feature
git rebase main

# 3. 충돌 해결 후
git add .
git rebase --continue

# 4. Force Push (권장하지 않지만 필요시)
git push --force-with-lease origin feature/my-feature
```

## 팀 규칙 설정

### 브랜치 보호 규칙

GitHub: Settings → Branches → Add rule

```
✅ Require pull request reviews before merging
   - Required reviewers: 2 (예시)
✅ Require status checks to pass before merging
   - GitHub Actions 통과 필수
✅ Include administrators
❌ Allow force pushes
❌ Allow deletions
```

### CODEOWNERS

파일별 소유자를 지정합니다.

```
# .github/CODEOWNERS
# 각 섹션의 라인이 파일 패턴과 소유자를 지정합니다.

# 모든 파일
* @org/team

# 특정 디렉토리
/src/auth @org/auth-team
/src/api @org/api-team

# 특정 파일
*.md @org/docs-team
```
